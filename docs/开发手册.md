> Nuxt MCP

Nuxt MCP 接入指南

本仓库为 Nuxt 项目（使用 yarn）。下文以 yarn 为主，括号内附 npm / pnpm 写法。

一、三者区别与选型

1.1 @nuxtjs/mcp-toolkit（官方模块，生产级，推荐）
- 做什么：为你的 Nuxt 应用本身添加一个 MCP Server，把应用的自定义功能（工具 / 资源 / 提示词）暴露给任意 AI 客户端（Cursor、VS Code、Claude Code 等）调用。
- 适合场景：想让 AI 直接调用你应用里的能力（例如查询数据、触发业务逻辑）。
- 状态：Nuxt 官方维护，可生产使用。

1.2 nuxt-mcp-dev（即此前所说的 nuxt-mcp，antfu 实验性）
- 做什么：给本地 nuxt dev 开发服务器加一个 MCP Server，让 AI 助手更好地理解你的 Nuxt 项目结构（路由、组件、配置等），从而辅助开发；默认还会自动注册 Nuxt 官方文档 MCP（https://nuxt.com/mcp）。
- 适合场景：开发阶段，让 AI 更懂你的代码库、辅助写代码。
- 状态：实验性（Experimental. Use with caution.）。antfu 本人也建议"要为应用建 MCP Server 请用上面的 toolkit"，二者定位不同。

1.3 Nuxt Agent / 官方 MCP Server（https://nuxt.com/mcp）
- 做什么：Nuxt 官方托管的 MCP 服务，让 AI 查询 Nuxt 官方文档。
- 注意：这是托管服务，不是要你安装到项目的包。只需把它配进 AI 客户端即可。装 nuxt-mcp-dev 时会默认带上它。

1.4 是否需要全部安装？
不需要全部安装，三者定位不同、可叠加但非必须：
- 让 AI 调用你应用的功能：装 @nuxtjs/mcp-toolkit
- 让本地 AI 助手辅助理解代码：装 nuxt-mcp-dev
- 只想让 AI 查文档：仅配置 https://nuxt.com/mcp，无需装包

1.5 本仓库推荐
- 若目标是「让 AI 辅助开发本仓库」：装 nuxt-mcp-dev（一键附带官方文档 + 项目结构理解）。
- 若目标是「把本应用能力开放给 AI」：装 @nuxtjs/mcp-toolkit。
- 二者可同时装，互不影响。

二、方案 A：@nuxtjs/mcp-toolkit（官方，推荐）

2.1 安装
方式一（推荐），自动安装并写入 nuxt.config.ts：

```bash
npx nuxt add mcp
```

方式二，手动安装（需同时装对等依赖 zod）：

```bash
yarn add @nuxtjs/mcp-toolkit zod
npm install @nuxtjs/mcp-toolkit zod
pnpm add @nuxtjs/mcp-toolkit zod
```

2.2 注册模块（nuxt.config.ts）

```ts
export default defineNuxtConfig({
  modules: ['@nuxtjs/mcp-toolkit'],
  mcp: {
    name: 'IPlay-Compression MCP',
    route: '/mcp',
    dir: 'mcp',
  },
})
```

2.3 定义工具（自动发现，零配置）
在 server/mcp/ 下按约定建文件，模块会自动扫描并注册，defineMcp 辅助函数自动导入，无需手动 import：

```
server/
└── mcp/
    ├── tools/        定义工具
    ├── resources/    定义资源
    └── prompts/      定义提示
```

示例 server/mcp/tools/hello.ts：

```ts
import { z } from 'zod'
import { defineMcpTool } from '@nuxtjs/mcp-toolkit/server'

export default defineMcpTool({
  name: 'hello',
  description: '向应用问好',
  inputSchema: { message: z.string() },
  handler: async ({ message }) => `Hello: ${message}`,
})
```

2.4 启动与连接 VS Code
1. 启动开发服务器：yarn dev（默认 http://localhost:3000/mcp 即 MCP 端点）。
2. 一键把 MCP 注册进客户端（支持 Cursor / Claude Code / VS Code / Codex）：

```bash
npx add-mcp http://localhost:3000/mcp
```

3. 或手动在 .vscode/mcp.json 写入：

```json
{
  "servers": {
    "iplay-compression": {
      "type": "http",
      "url": "http://localhost:3000/mcp"
    }
  }
}
```

生产环境将 url 改为 https://你的域名/mcp，自定义过 mcp.route 则相应改路径。

4. （可选）限制暴露的工具，加 headers：

```json
{
  "servers": {
    "iplay-compression": {
      "type": "http",
      "url": "http://localhost:3000/mcp",
      "headers": { "X-MCP-Tools": "hello" }
    }
  }
}
```

三、方案 B：nuxt-mcp-dev（开发辅助，实验性）

3.1 安装

```bash
yarn add nuxt-mcp-dev
npm install nuxt-mcp-dev
pnpm add nuxt-mcp-dev
```

3.2 注册模块（nuxt.config.ts）

```ts
export default defineNuxtConfig({
  modules: ['nuxt-mcp-dev'],
  mcp: {
    updateConfig: 'auto',
    includeNuxtDocsMcp: true,
  },
})
```

modules 加 'nuxt-mcp-dev' 的最小配置即可启用。updateConfig 可选值：'auto' / true / false / ['vscode','cursor']；includeNuxtDocsMcp 默认 true，附带官方文档 MCP。

3.3 暴露的端点
启动 yarn dev 后，MCP Server 默认在：

```
http://localhost:3000/__mcp/sse
```

（端口随 Nuxt devServer.port 变化，SSE 路径固定为 /__mcp/sse。）

3.4 连接 VS Code
模块开启 updateConfig 时会自动在 .vscode/mcp.json 以名称 nuxt 注册并附带官方文档 MCP。也可手动写入：

```json
{
  "servers": {
    "nuxt": {
      "type": "sse",
      "url": "http://localhost:3000/__mcp/sse"
    }
  }
}
```

四、仅接入官方文档 MCP（最简，无需安装任何包）
把 Nuxt 官方文档 MCP 直接配进 .vscode/mcp.json 即可让 AI 查文档：

```json
{
  "servers": {
    "nuxt-docs": {
      "type": "http",
      "url": "https://nuxt.com/mcp"
    }
  }
}
```

五、验证
- 启动 yarn dev。
- 打开 VS Code 的 MCP / 工具面板，确认对应 server（如 iplay-compression / nuxt / nuxt-docs）状态为已连接。
- 在 AI 对话中尝试调用工具或询问 Nuxt 文档问题，验证是否生效。

六、面向 AI 的使用提示词（可直接复制粘贴）
把下面代码块的内容整体复制，粘贴给任意支持 MCP 的 AI 客户端（如 CodeBuddy、GitHub Copilot、Claude、Cursor）。AI 在连接本仓库的 MCP server 后会据此与你协作。

```
你是 IPlay-Compression（一个基于 Nuxt 的图像压缩 Web 工具）的编程助手。本仓库已为你接入以下 MCP 能力，请优先使用它们：

1. 应用 MCP Server（来自 @nuxtjs/mcp-toolkit）
   端点：http://localhost:3000/mcp（类型 streamable-http）
   用途：调用本应用自定义的 MCP 工具 / 资源 / 提示词。
   已注册工具示例：hello（输入 message 字符串，用于验证连通性）。
   扩展方式：在 server/mcp/tools、server/mcp/resources、server/mcp/prompts 下新增文件即被自动发现，无需手动注册。

2. 开发辅助 MCP（来自 nuxt-mcp-dev）
   端点：http://localhost:3000/__mcp/sse（类型 SSE）
   用途：帮助你理解本仓库的 Nuxt 项目结构（路由、组件、配置、依赖），辅助开发与重构。
   注意：仅用于读取与理解，不要依赖它直接修改项目文件。

3. Nuxt 官方文档 MCP
   端点：https://nuxt.com/mcp（类型 streamable-http）
   用途：查询 Nuxt 3 / 4 官方文档、API 与模块用法。遇到 Nuxt 相关问题优先查询此来源。

协作约定：
- 图像处理全程在本地完成，图片不上传服务器。
- 优先使用上述 MCP 获取最新、权威信息，而非凭记忆作答。
- 修改代码前，先用开发辅助 MCP 确认相关文件与依赖关系。
- 若要为应用新增可被 AI 调用的能力，在 server/mcp/ 下按约定创建文件，遵循 defineMcpTool / defineMcpResource / defineMcpPrompt 的写法。
```

七、本仓库已落地的配置文件
- package.json：已加入依赖 @nuxtjs/mcp-toolkit、nuxt-mcp-dev、zod（及开发依赖 nuxi）。
- nuxt.config.ts：modules 已加入两个 MCP 模块，并在 mcp 配置块中合并两者字段（toolkit 用 name/route/dir，nuxt-mcp-dev 用 updateConfig/includeNuxtDocsMcp）。
- server/mcp/tools/hello.ts：示例 MCP 工具，用于验证连通性。
- .vscode/mcp.json：声明三个 server（iplay-compression 指向 /mcp、nuxt-dev 指向 /__mcp/sse、nuxt-docs 指向官方文档）。
- 验证结果：yarn dev 后 /mcp 返回 405（仅接受 POST）、/__mcp/sse 返回 200（SSE 握手成功），两个端点均正常。
